# UI 与输入契约

本应用的所有页面和菜单都必须遵守以下规则。这些规则来自反复出现的缺陷：
标题/状态栏重叠、按键不跟随屏幕方向、松开才触发、菜单不能循环。

## 顶部布局

- 顶部保留状态栏区域：时间、电量。
- 页面标题放在状态栏下方；如果标题居中，时间应移到左上角。
- 标题和状态栏不得使用同一个 `y` 坐标。
- 版本号只显示在首页。
- 需要整屏的页面（例如参考尺）必须显式隐藏状态栏，并清空时钟标签指针。

## 按键语义

- 页面只接收 `ARCHERY_KEY_UP`、`ARCHERY_KEY_DOWN`、`ARCHERY_KEY_OK`、
  `ARCHERY_KEY_OK_LONG`。
- 物理键到逻辑键的映射（包括 180° 屏幕倒转）只在应用输入层做一次；
  页面禁止读取 `rotate` 或物理键编号。
- 每个菜单都要测试 `rotate = 0` 和 `rotate = 1`，两种方向下按键方向必须一致。

## 按下触发

- 导航和数值修改在 `BSP_BTN_PRESS` 触发，不等松开。
- 按下触发后设置 `s_repeat_used`，吞掉松开产生的 click。
- 长按只触发长按动作；同时有短按/长按语义的页面不能让短按执行两次。
- 松开时停止连发；页面切换后不得继续投递旧按键。

## 菜单循环

- 菜单顶部按上跳到底部，底部按下跳到顶部。
- 扫描到的 Wi-Fi 列表可以 clamp，避免误选“返回”时触发连接。
- 任何多行菜单都要测试上下两个边界。

## UI 改动的完成标准

```text
[ ] 标题、时间、电量、版本号不重叠
[ ] rotate 0/180 下方向一致
[ ] 上/下/确定按下立即响应
[ ] 菜单两端可循环
[ ] 连续调值不整页重绘
[ ] validate.sh --static 通过
```

## 连续控件

连续移动的控件不要每个 tick 都重建整屏；保留对象句柄，只更新位置/文字。
否则 80 ms 连发可能耗尽 LVGL 内存并导致设备重启。
